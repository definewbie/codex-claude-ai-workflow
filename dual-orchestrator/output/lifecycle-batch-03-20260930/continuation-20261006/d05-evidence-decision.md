# D05 机器执行证据：语义已确认，接线未完成

状态：2026-10-06 用户已明确采纳下述决定，原异步澄清已被本次答复解决。此处更新设计语义，不代表实现、回归或 B03 已完成；未启动 provider/native，未把不确定值填成 0。

## 用户确认的决定

> 不再把“真实退出码”强制设为所有验收的统一门槛；每项验收需要什么证据，就检查什么证据。明确要求退出码的，仍必须取得。

本决定替代原 D05 对机器证据一律要求实际 exit 的口径；不自动改写任何已批准任务的验收标准。原生工具的结构化状态可以作为执行观察，不能单独证明验收通过。原生状态与真实退出码是两种可同时存在的事实，不是互斥的“三态”；真实退出码不可得时明确记录缺失，不从原生状态合成。

是否需要实际退出码及其要求，应在执行前随对应 criterion 的验证方案明确，经既有复评与 EXECUTION 批准固定。不能把“尚未明确”默认为“不需要”，不能在拿到结果后由模型、adapter 或 validator 删除要求。已批准标准明确要求实际退出码时，缺失就保留证据缺口；调整标准须走既有重新批准路径。

| 已批准要求与实际材料 | 必须得到的结果 |
|---|---|
| 要求测试报告证明具名测试全部通过，未要求实际退出码；工具输入/结果、报告来源、当前源码和断言均可核验 | 不因缺退出码一律拒绝；仍经独立验收核查报告是否满足该项要求 |
| 要求报告通过且实际退出码为 0；报告通过但只有原生“成功”状态或合成 0 | 证据不足，不得通过或借外层 acpx exit 代替 |
| 要求实际退出码为 0；真实退出码非 0、工具却报告成功 | 不满足该要求；两种观察均保留，不能覆盖真实失败 |
| 只有工具“成功”或模型自述“全部通过”，缺少对应断言/结果材料 | 不能据此证明测试全部通过 |
| 材料属于旧源码、错 execution/session/tool call，或引用字节已变 | 拒绝复用；退出码是否为 0 不改变该结论 |
| 相同适用源码、执行身份与已批准要求下的完整证据仍有效 | 允许合法复用；不为缺少未要求的退出码强制重跑 |

以上是待实现的合法/拒绝对照，全部 NOT RUN，不增加新测试执行器、通用断言 DSL 或原生实验预算。

## 接线顺序与拒绝时点

1. 计划/合同 owner 固定每项 criterion 的证据要求；首次执行前由现有 compiler/qualification 消费，未明确的必需验证出口不可借本决定跳过。
2. adapter/runtime 记录同一次实际工具调用的输入、结果、原生状态、可取得的实际退出码及来源；模型输出仅作断言与引用候选，不产生执行事实。
3. 自测/验收消费者核对批准要求、工具调用身份、材料引用和源码基准。缺必需证据时阻止采纳/成功推进，沿既有补证据或返修路径继续；不把事后证据校验说成操作系统写前拦截。
4. D06/D07 仍负责固定判定与写集：持久化未完只续完同次本地提交，外部执行未知不自动重发；恢复与交付不得从缺失/合成退出码推导新成功事实。

具体字段与入口需沿既有 TaskContract verification binding、typed tool event、固定 run 完成和证据消费者接通并验证；本决定不宣称这些接线已经存在。新增断言通用执行机制或改变批准标准仍超出当前决定。

## 已核实事实

固定 Claude ACP 0.70.0 的 tools.js（源码身份与带行号片段见同目录 claude-tool-result-source.json/txt）：普通 Bash 返回的 terminal_exit.exit_code 初值来自 is_error ? 1 : 0；structured Bash 的 stdout/stderr 并不带真实子进程退出码，interrupted 又会把该值置为 1。只有另一个明确的 bash_code_execution_result 分支直接消费 return_code。故不能将所有 terminal_exit.exit_code 一律解释为真实 shell exit code，也不能推导所有原生接口都不提供真实退出码。

此问题与 Dual 启动的 acpx 进程退出码不同。现有外层 processResult 真实，也不能代证内部测试命令。工具计数、模型正文、operator 事前可用性声明同样不能代替实际机器执行证据。

## 确认前的选择与依赖（历史）

- 接受具名原生工具的结构化完成/失败状态作为一种机器执行观察，与真实 input/output、源码身份和独立断言一起消费；字段必须区分 native-reported status、真实 process exit、无法取得退出码。此项需要确认，不默改冻结 D05 对真实 exit 的要求。
- 若必须取得每个内部测试进程的真实退出码，则保持该验收条件，进一步限定可使用的既有证据生产者；没有证据的执行出口不可假装满足。不得默认增加通用 runner、认证平台或引擎改造。

上述第一项已按本次用户决定采纳，并保留第二项中“验收明确要求实际退出码时必须取得”的约束。程序事实正向复用、permission signal 与 criterion 的精确关联、机器证据验收消费尚未完成。当前测试中模拟 agent 输出的 ACCEPT/self-test 只证明生命周期和授权路由，不证明 D05 的真实机器执行证据成立。不能因这些序列全绿便关闭 W04/I4 或 B03。

## 边界

Declared：D05/W04。Owner：程序执行观察由 adapter/runtime 拥有；模型只提交语义断言。Consumed：编译/准备/自测-验收/交付的既有消费者，不能以文件存在代证。Enforced before：相应采纳/推进之前，非操作系统写前防护。Failure route：缺证据保留缺口，不伪造 exit 或自动重跑。Cannot-bypass：后续必须成对证明合法机器证据通过、纯模型声明/合成 exit/错命令/错源码身份拒绝；当前尚无完成证明。
