# 启动核验离线修正：开工边界

目标 P0：修正真实 Gate 启动准入中的进程观察误判，使未知权限状态不能被当作已停止；核清启动超时证据链。P0.5：保留 UNAVAILABLE 与无 prompt 记录的区别。P0 完整主流程未证，不进入节省策略或沙箱建设。

Definition：原 Gate / 预算 / 流程不改。Instance：第七例停止账本只读。Execution：原会话命令 timeout/outcome 为 SoT。Gate operator 的本地 ps 观察是本次 owner，不产生领域状态或批准；新候选只用于未来重审，不更改第七例受审脚本和历史 PASS。

分级：这不是模型瞬断重试。进程核验承担启动准入，按 BOUNDARY 的证据纪律处理；修正仅在非产品的离线 Gate 候选，产品 Java/registry/协议/JAR 均无变动，不能通过重跑 Maven 为这个 operator 缺陷提供证明。验证针对真正消费路径、失败前无启动与冷进程，独立 CC 复审保留给候选，作者不冒充独立评审。若需要产品改动，先提交范围与成本判断。

| 前态/SoT | 行为与顺序 | 后态/唯一消费 | 失败/恢复 |
|---|---|---|---|
| 外部进程状态未知 | 一次完整 ps 成功读取→严格校验退出码/错误输出/非空结构→比对已知 PID | 仅完整读表且所有目标 PID 缺席才有 ABSENT 观察 | 无权/超时/异常/畸形/空表→UNKNOWN，不创建或派发 |
| 完整读表发现目标 PID | 返回 PRESENT | Gate 前置拒绝 | PID 重用也保守拒绝，人工再查；不杀进程 |
| ABSENT | 原 pre-dispatch 后续冻结输入/Git/预算核对 | 本地检查可通过，不授批准或 native 回复资格 | 任一后续失败不写 PASS；下次必须重读，不复用快照作许可 |
| 核验脚本冷启动 | 重新读表，旧报告无许可 | 只读观察 | 不恢复第七例、不移除 stop-required、不建立新例 |
| 第七例会话超时固定 | 静态源码→原命令记录→本机解析链/日志核对 | 确认事实和未证推测分列 | 不执行真实 sessions new/prompt，不放宽超时/权限，不将模拟链当事故根因 |

兄弟入口：prepare-offline.py 与 pre-dispatch-recheck.py 两处旧模式须在同一候选使用同一进程核验；不回写任何历史准备包。六维最终报告须说明：Declared / Proven / Consumed / Enforced before / Failure route / Cannot-bypass。

成本上限：一个标准库进程观察 helper、两个既有脚本的候选副本、成对测试与源码/旧材料只读核对；不做新常驻服务、权限平台、进程树监督、真实网络/模型实验。超时定位若缺少历史初始化/子进程日志，明确标未证，不靠更多猜测扩张。
