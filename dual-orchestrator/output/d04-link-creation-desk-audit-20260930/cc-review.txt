2. 核心问题：布局前提还是能力缺口——按角色分裂

只读角色：可维持的布局前提。 §8.24 的只读组合工具面为 Read/Grep/Glob——没有任何写/执行工具，硬链接无所谓穿透（无物可写）。准备期对控制树做 nlink>1 扫描即可完备拒绝预存别名（硬链接的所有路径都计入控制文件的 nlink，扫描控制树即覆盖任意位置的别名）；运行期模型无工具创建新链接。前提可查且不可破——候选对只读角色保持成立。

implement 角色：尚无机制守住的能力缺口。 机制分析（非实验外推）：implement 含 Bash，同 OS 用户、同文件系统下，运行期 ln <control> work/newlink 后经可写路径写入——ln 只触碰可写路径并引用可读路径，路径规则在原理上不可见此操作；macOS 无同用户 hardlink 限制。因此“无别名”条件在执行期无既有机制维持（fsevents/inotify 类监控不在现有方向内；inodel 级沙箱规则不经 profile 接口暴露）。预存检查+收尾检查能事后检出（本 Gate 的外部守卫正是这么发现并停止的），但写前阻止不可达。注意：该缺口早于委派与 carve-out 设计存在（今日任何含 Bash 的 implement agent 同权），本 Gate 只是首次给出实证。
