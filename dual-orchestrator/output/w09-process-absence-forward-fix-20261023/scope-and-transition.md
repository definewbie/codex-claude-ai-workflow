# 离线进程核验候选：开工边界

目标：P0 主流程验证阻塞的直接修正。通过既有“成功读表确认旧 PID 缺席”的历史事实，避免以后同一数字再出现导致误拒；对从未成功确认缺席的目标仍严格检查。P0 整体未 Promoted，本轮不声称主流程完成、不做 P1/P2/P3。

性质：验证准入事实的消费规则调整，按边界敏感项处理，不当 TRANSIENT 自动续跑。只制作离线候选；不修改 Java 产品、冻结发行、当前 Gate、当前账本或历史停止结论。源码型候选不是已获准的新 Gate。未来接线仍需受影响独立复审与真实运行授权。

Definition 是已批准的旧 Gate 规则；Instance 是停止的第八例；Execution 是具体 OS 进程及成功/失败观察。旧 PID 缺席是有时间与范围的执行观察，不能等同任意子树/远程已停。脚本不是业务状态 owner。

事实 owner：原成功完整进程检查产生 absent=true 记录，当前 Gate 固定输入 SHA 保证该记录来源未被替换。只有程序产生且已绑定原始依据的记录可以作为历史确认；不能把普通用户/模型 JSON 的 absent=true 当证明。没有新服务、锁、持续监控账本或“按命令判断是否安全”的机制。

生产和消费分开：prepare 是首次生产者，丢弃输入清单上的 absent 标记、实际检查全部原始 PID；成功后才写观察与 old-execution-recheck.json。pre-dispatch 与 runner 是后续消费者，须先通过既有 frozen_check 核对已固定记录，再复用其 absent=true。首次生产者不能凭待检查输入上的同名字段免检。本轮未执行首次准备，也未生成新的 launch-identity；未来 Gate 装配必须把新脚本与程序生成的记录一并绑定。

前向修复：未来所有“已确认退出后号码再分配”的状态适用。不为83976写特例，不恢复第八例，不回填触发当刻的进程身份。不做 PID+启动时间平台；未确认的 PID 即使可能复用，仍停止，因现有证据不足。

回归范围：本轮只执行完整辅助模块测试、三个真实消费者的原语句/顺序拒绝检查、冷子 Python 重读、固定旧材料对照和隔离删除反证。Java 源码/发行不动，历史 Maven PASS 不冒称本候选的证明，也不为候选重建产品发行。完整新 Gate 装配尚未运行。

保留限制：首次准备仍可能因一个尚无可信缺席记录的号码实际出现而停止；不通过本轮顺便新增 PID 启动身份追踪。历史确认只覆盖对应旧进程，不证明其任意子树或远程作业停止。辅助函数自身不验证文件来源，必须由前置固定输入检查与生产接线共同承担，不能在其他入口直接喂任意 absent=true 后宣称具备证明。
