## Completed This Session

### Commit e3603b4: Prompt injection hardening

Three security defects found and fixed in `DualControlBlockParser` + `ReviewDecisionHandler`:

1. **Regex line-start anchor** — Pattern changed from ` ```dual-control` to `(?m)^```dual-control...^``` `, preventing blockquote `> ```dual-control` and nested code fence injection.
2. **Terminal block rule** — Replaced `MULTIPLE_DUAL_CONTROL_BLOCKS` error. Only the last `dual-control` block is the control directive; earlier blocks treated as prose.
3. **No cross-file fallback** — `ReviewDecisionHandler.readLatestControlBlock` returns whatever the latest file contains (valid, invalid, or missing), never falls back to older files.

Also added: `CheckpointDocumentTest` (15 tests), `CodexReviewControlTest` (21 tests), ~28 new `BuiltinHandlerTest` injection scenarios, updated README and smoke-test-full.md.

## Important Context for Continuation

### Memory file principle
Integration code discipline: trace the call chain to actual I/O points before writing code. Four derived rules:
1. Fixes must not introduce worse bugs — check all call sites for semantic changes
2. Understand termination conditions before writing loop/startup logic
3. Side effects must be opt-in with explicit flags
4. Cleanup in reverse creation order
