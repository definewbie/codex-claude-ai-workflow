### T1.4 Runtime Hardening

Commit `f4bc606`: Full T1.4 implementation — fix 2 production bugs, add per-failure-type retry policies. +155/-33, 6 files.

#### Bugs Fixed

**Bug 1: Data contract mismatch** — `AcpxAgentTaskHandler` wrote `recoverable`/`failure_reason` but `WorkflowRuntime` read `acpx_failure.recoverable`/`acpx_failure.reason`. Auto-retry would never trigger in production. Keys now aligned.

**Bug 2: Auto-retry unreachable** — When a handler returns FAILED, `completeAndRoute()` → `stopOnNonCompletedNode()` sets `WAITING_FOR_RECOVERY`. On next `resume()`, the WAITING_FOR_RECOVERY early return blocked execution before `resolveFailedNode()` was ever reached. The auto-retry code was dead.

#### Architecture Changes

**Before T1.4:**
```
resume() → WAITING_FOR_RECOVERY? → reject immediately
         → resolveNodeForExecution()
              → READY: execute
              → RUNNING: check PID
              → FAILED: auto-retry (dead code — never reached)
```

**After T1.4:**
```
resume() → WAITING_FOR_RECOVERY?
              → load active node
              → FAILED + recoverable + under threshold?
                  → autoRetryNode() → reset to READY → fall through to execution
              → else: reject with specific message
         → resolveNodeForExecution()
              → READY: execute
              → RUNNING: check PID
              → FAILED/BLOCKED/WAITING/...: null (handled above)
```

The key change: auto-retry is now the **first check** when workflow is WAITING_FOR_RECOVERY, not buried in a later guard that's never reached.

## Important Context

### Design decisions this session

1. **Auto-retry lives in WAITING_FOR_RECOVERY gate** — not in resolveNodeForExecution(). Reason: by the time resolveNodeForExecution() runs, FAILED nodes have already been routed through stopOnNonCompletedNode() which sets WAITING_FOR_RECOVERY. The old code was unreachable.
2. **Namespaced keys (`acpx_failure.*`)** — chosen over flat keys to avoid collision with other result map entries and to make the contract explicit in tests.
3. **FAILED removed from resolveNodeForExecution()** — it's now null (rejected). All FAILED handling goes through the WAITING_FOR_RECOVERY path. This avoids confusion about which code path handles FAILED nodes.
4. **RetryPolicy.delayForAttempt() exists but unused** — computed delay is available for future use. No Thread.sleep in the synchronous resume() path yet.

### Memory principle
Integration code discipline: trace the call chain to actual I/O points before writing code. This session's Bug 1 (key mismatch) and Bug 2 (unreachable code) are examples of why this matters — the test bypassed the real flow and masked both bugs.
