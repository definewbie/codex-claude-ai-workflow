## WorkflowFileLedger Refactoring Plan

### Current: 860 lines, ~35 methods, 4 mixed responsibilities

**Problem**: Hard to test in isolation, hard to extend, any change risks side effects across unrelated concerns.

### Proposed: Facade + 4 internal delegates

```
WorkflowFileLedger (facade, ~100 lines)
  ├── LedgerEventLog (~80 lines)     — appendEvent, writeInstanceFromCurrent, ID helpers
  ├── RevisionTracker (~120 lines)   — iteration tracking, revision counting, blockOnRevisionLimit
  ├── NodeStateWriter (~200 lines)   — markRunning, autoRetryNode, retryActiveNode, abortRecovery
  ├── RoutingEngine (~350 lines)     — completeAndRoute, resolveOpenGate, completeWorkflow, stopOnNonCompletedNode
  └── LedgerUtils (~60 lines)        — static utility methods
```

### Extraction Map

#### LedgerUtils (static, no state)

Move these static methods to a utility class:
- `resultValue`, `resultValueOrDefault`, `firstNonBlank`, `text`
- `allowedActions`, `revisionReason`, `mergedResult`
- `isControlRepairFailure`

### What stays in the Facade

- `initialize()` — one-time bootstrap, ~60 lines, not worth a class
- `loadCurrent/loadDefinition/loadNode/loadCoreNode` — trivial 1-liners shared by all delegates
- Constructor — wires all delegates together
- Public delegate methods — one-liner forwarding calls

### Dependency Graph

```

LedgerEventLog       (AtomicJsonWriter, jsonlMapper)
```

### Implementation Order

1. Extract `LedgerUtils` — move static methods, update references

3. Extract `RevisionTracker` — depends on LedgerEventLog
4. Extract `NodeStateWriter` — depends on LedgerEventLog
