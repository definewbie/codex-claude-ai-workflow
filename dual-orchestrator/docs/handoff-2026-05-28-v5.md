## WorkflowFileLedger Refactoring Plan

### Current: 860 lines, ~35 methods, 4 mixed responsibilities

**Problem**: Hard to test in isolation, hard to extend, any change risks side effects across unrelated concerns.

### Proposed: Facade + 4 internal delegates

```
WorkflowFileLedger (facade, ~100 lines)
  ├── LedgerEventLog (~80 lines)     — appendEvent, writeInstanceFromCurrent, ID helpers
  ├── RevisionTracker (~120 lines)   — iteration tracking, revision counting, blockOnRevisionLimit
  ├── NodeStateWriter (~200 lines)   — markRunning, autoRetryNode, retryActiveNode, abortRecovery
  ├── RoutingEngine (~350 lines)     — completeAndRoute, resolveOpenGate, completeWorkflow, stopOnNonCompletedNode
  └── LedgerUtils (~60 lines)        — static utility methods
```

### Extraction Map

#### LedgerUtils (static, no state)

Move these static methods to a utility class:
- `resultValue`, `resultValueOrDefault`, `firstNonBlank`, `text`
- `allowedActions`, `revisionReason`, `mergedResult`
- `isControlRepairFailure`

#### LedgerEventLog

| Method | Depends on |
|---|---|
| `appendEvent(paths, eventId, eventType, payload)` | `jsonlMapper` |
| `writeInstanceFromCurrent(paths, current, updatedAt)` | `jsonWriter` |
| `nextEventId(lastEventId)` | static |
| `currentEventNumber(eventId)` | static |
| `nodeInstanceId(definitionId, sequence)` | static |
| `stageId(nodeDefinitionId)` | static |

Constructor: `(AtomicJsonWriter, ObjectMapper jsonlMapper)`

#### RevisionTracker

| Method | Depends on |
|---|---|
| `nextRevisionIteration(paths, ...)` | `jsonWriter`, `objectMapper`, `readIterationOrNull` |
| `blockOnRevisionLimit(...)` | `jsonWriter`, `eventLog`, `loadCurrent`, `loadNode` |
| `maxIterationNumber(paths)` | Files.list |
| `revisionCount(paths, targetNodeDefId)` | `readIterationOrNull` |
| `readIterationOrNull(path)` | `objectMapper` |
| `startsNewIteration`, `isRevisionAction`, `maxRevisions` | static |

Constructor: `(AtomicJsonWriter, ObjectMapper, LedgerEventLog)`

#### NodeStateWriter

| Method | Depends on |
|---|---|
| `markRunning(paths, nodeInstanceId, pid)` | `jsonWriter`, `loadNode` |
| `autoRetryNode(paths, nodeInstanceId)` | `jsonWriter`, `loadNode`, `loadCurrent`, `eventLog` |
| `autoRetryNode(paths, nodeInstanceId, retryDelayMs)` | same as above |
| `retryActiveNode(paths, note)` | `jsonWriter`, `loadCurrent`, `loadNode`, `eventLog` |
| `abortRecovery(paths, note)` | `jsonWriter`, `loadCurrent`, `loadNode`, `eventLog` |

Constructor: `(AtomicJsonWriter, ObjectMapper, LedgerEventLog)`

#### RoutingEngine

| Method | Depends on |
|---|---|
| `completeAndRoute(...)` | `jsonWriter`, `loadCurrent`, `loadNode`, `revisionTracker`, `eventLog` |
| `completeWorkflow(...)` | `jsonWriter`, `eventLog` |
| `stopOnNonCompletedNode(...)` | `jsonWriter`, `eventLog` |
| `resolveOpenGate(...)` | `loadCurrent`, `loadNode`, `completeAndRoute` |
| `recoveryGateResult(...)` | static, LedgerUtils |

Constructor: `(AtomicJsonWriter, ObjectMapper, LedgerEventLog, RevisionTracker)`

### What stays in the Facade

- `initialize()` — one-time bootstrap, ~60 lines, not worth a class
- `loadCurrent/loadDefinition/loadNode/loadCoreNode` — trivial 1-liners shared by all delegates
- Constructor — wires all delegates together
- Public delegate methods — one-liner forwarding calls

### Dependency Graph

```
LedgerUtils          (no deps, static)
LedgerEventLog       (AtomicJsonWriter, jsonlMapper)
RevisionTracker      (AtomicJsonWriter, objectMapper, LedgerEventLog)
NodeStateWriter      (AtomicJsonWriter, objectMapper, LedgerEventLog)
RoutingEngine        (AtomicJsonWriter, objectMapper, LedgerEventLog, RevisionTracker)
WorkflowFileLedger   (creates all above, delegates public calls)
```

### Implementation Order

1. Extract `LedgerUtils` — move static methods, update references
2. Extract `LedgerEventLog` — move appendEvent + writeInstanceFromCurrent + ID helpers
3. Extract `RevisionTracker` — depends on LedgerEventLog
4. Extract `NodeStateWriter` — depends on LedgerEventLog
5. Extract `RoutingEngine` — depends on LedgerEventLog + RevisionTracker
6. Thin `WorkflowFileLedger` to facade

Run `mvn clean test` after each step. All 269 tests must pass.

### File Layout

All in `dual-ledger-file/src/main/java/dev/dual/ledger/file/`:

```
LedgerUtils.java         — static utility methods (package-private)
LedgerEventLog.java      — event append + instance write
RevisionTracker.java     — iteration/revision tracking
NodeStateWriter.java     — markRunning, autoRetry, retry, abort
RoutingEngine.java       — completeAndRoute, resolveOpenGate, routing
WorkflowFileLedger.java  — thin facade (~100 lines)
```

### Public API — Unchanged

All external callers (WorkflowRuntime, 8 CLI commands) continue using `WorkflowFileLedger` with identical method signatures. No import changes needed outside `dual-ledger-file`.
