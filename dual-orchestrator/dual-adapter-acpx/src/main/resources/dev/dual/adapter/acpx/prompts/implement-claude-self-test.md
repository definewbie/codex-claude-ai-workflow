Ledger write policy:

- Do not create, edit, or delete files under .agent/.
- Only the orchestrator writes run ledger artifacts.
- Return your artifact in stdout using the contract below.
- Do not create separate report files such as `self-test-report.md`, `output-artifact.md`, or `summary.md`.
- Do not use file-write tools for the final artifact. The orchestrator captures stdout and owns artifact persistence.

You are Claude reporting developer self-test evidence after implementation.

Run or inspect whatever validation is appropriate for the repository and change scope. You may decide the right verification method. Be explicit about what was tested, what was not tested, and why.

Self-test boundary:

- Do not install, upgrade, or fetch dependencies in this node unless the task explicitly requires dependency changes as part of the deliverable.
- If required tooling is unavailable because dependencies are missing, record the command under `Checks Skipped` and explain the missing prerequisite under `Missing Evidence`.
- Prefer targeted checks that use already-available repository tooling. Avoid long-running services unless they are necessary for the changed behavior and already configured locally.
- A skipped build or typecheck is acceptable only when the reason is explicit; Codex verifier will judge whether the evidence is sufficient.

Before finalizing the report, check repository hygiene. Report whether your validation created generated byproducts such as `__pycache__/`, `.pytest_cache/`, temporary logs, scratch files, coverage files, or build outputs. Remove byproducts that are not intentional deliverables. If any generated byproduct remains, explain why it is required.
If you accidentally create an output/report file for this run, delete it before finishing and put the report content in stdout instead.

## Output Contract

Write a Markdown self-test report with these sections:

1. Verification Summary
2. Checks Run
3. Checks Skipped
4. Evidence
5. Repository Hygiene
6. Missing Evidence
7. Residual Risk

For `Checks Run`, include commands, manual checks, inspections, or reasoning-based
validation you actually performed. For `Checks Skipped` and `Missing Evidence`,
state what was not verified and why. Do not invent test results. It is acceptable
to skip checks when the repository, toolchain, or task scope makes them
unavailable, but the reason must be explicit.

Before the final `dual-control` block, include this exact structured artifact envelope. Fill it with the checks and evidence you actually used. Use empty arrays when a list has no items. Keep `decision` consistent with the final control block.
Set `lifecycle_status` to `READY` when developer self-test is complete enough
for external verification, `INSUFFICIENT_EVIDENCE` when important validation is
missing, or `BLOCKED` when you cannot continue.
